## MyLauncher 图标提取代码审查（未改代码，仅分析）

审查对象：`MyLauncher-src/src-tauri/src/lib.rs`（3707 行）

现状：图标提取只有一条路径
`SHCreateItemFromParsingName` → `IShellItemImageFactory::GetImage(256, SIIGBF_ICONONLY)`
→ 透明像素占比 ≥70% 则改取 48px → flip_vertical → 存 PNG

已确认的代码级缺陷：
1. `lib.rs:1026` get_shell_item_image 中 `factory.GetImage()` 返回的 HBITMAP 从未 `DeleteObject`，
   `GetObjectW` 返回值也未检查 → GDI 句柄泄漏。`batch_refresh_icons`（lib.rs:1700，8 线程）会放大影响。
2. `lib.rs:1076-1095` 用「透明像素占比 ≥70% 回退 48px」判断是否模糊 —— 判据无效。
   双线性缩放是线性的，alpha 占比缩放前后基本不变，识别不出「小图标被放大」。
   正确信号是返回位图的实际尺寸（请求 256 拿回 32/48 即说明只有小图标）。
3. `lib.rs:1282-1409` resolve_lnk_file 未调用 `IShellLinkW::GetIconLocation`
   → 「更改图标」过的快捷方式、以及指向 javaw.exe/msiexec.exe 等宿主程序的快捷方式都拿不到真实图标。
4. `lib.rs:1181`、`1392` 失败时 `unwrap_or_default()` 返回空串，无次选方案 → 前台空白图标。
5. `lib.rs:1110-1120` 命名用 `{stem}_{HHMMSSmmm}.png`，非字母数字全部替换成 `_`
   → 中文名/符号名易撞名；同条目重复提取每次产出新文件；无内容去重。

建议方向：改成四层有兜底的链
L1 解析真实图标源（lnk IconLocation / App Paths / 卸载项，支持 `file.dll,-101` 与 `exe,3` 写法）
L2 原生最大帧优先（PrivateExtractIcons / SHDefExtractIcon / ICO 多帧；不放大，裁透明边距）
L3 Shell 管线（SHGetFileInfo + SHGetImageList(SHIL_JUMBO)，与资源管理器一致）
L4 兜底规范化（按扩展名取类型图标 → 内置默认图，绝不返回空串）

缓存放后面再动：改内容哈希命名，可去重、可原子写、可共享（同一 exe 多条目共用一份 PNG）。

待用户拍板是否落地，落地方案未定。

## 系统功能图标方案（用户澄清真正要解决的问题，本机实测，未改代码）

用户澄清：图标提取算法已迭代多版、够清晰，不要动。真正的问题是
「添加 Windows 系统程序时用的是 emoji，不是系统图标」。

问题定位：
- src/data/systemTools.ts 42 项全写死 emoji，SystemAppPicker.pickTool 直接回传 emoji
- lib.rs refresh_icon_inner 对 system 类型直接返回"无需重新提取"

为什么不能简单改成"提取 target"（本机实测）：
- 10 项是 .msc → ExtractIconExW 返回图标数 0，Shell 对所有 .msc 返回同一通用图标
  （SHGetFileInfo 哈希 3a4cde9ac5，图像列表索引 0）→ 提取 .msc 不通
- 14 项是 ms-settings: URI → 没有对应文件
- 真正的 exe 约 18 项可提取，但裸命令需 SearchPathW 解析：
  regedit.exe 在 %windir%（非 System32）、powershell.exe 在 WindowsPowerShell\v1.0、
  Win11 的 mspaint.exe / snippingtool.exe 在 System32 已不存在

解法（已验证）：专属图标在独立 DLL 里，开始菜单快捷方式 IconLocation 记录了地址。
提取 API = PrivateExtractIconsW(file, group_index, 256, 256) → HICON → 现有链路转 PNG。
实测 33 项全部提取成功，均 256x256，图标各不相同。

已验证图标源（系统管理组）：
Taskmgr.exe / devmgr.dll@5(设备管理器,与CLSID权威-201哈希一致) / dmdskres.dll(磁盘管理,索引待挑)
miguiresource.dll@0(事件查看器)@1(任务计划程序) / filemgmt.dll(服务) / Mycomput.dll(计算机管理)
regedit.exe 在 %windir% / gpedit.dll(组策略) / wdc.dll@0(性能监视器)@1(资源监视器)
pmcsnap.dll(打印管理) / wsecedit.dll(本地安全策略) / cleanmgr.exe / msconfig.exe / msinfo32.exe
charmap.exe / psr.exe / comres.dll(组件服务) / AuthFWGP.dll(防火墙) / odbcint.dll(ODBC)
iscsicpl.dll(iSCSI) / RecoveryDrive.exe / MdSched.exe / Program Files\Hyper-V\SnapInAbout.dll

关键坑：
1) IconLocation 与 CLSID DefaultIcon 用负数资源ID形式（devmgr.dll,-201），
   但 PrivateExtractIconsW 对负数支持不稳定（-201 成功、-9/-22 失败）
   → 清单统一记录"组索引"(0-based)，运行时只走组索引这条已验证路径
2) Shell 管线(IShellItemImageFactory/SHGetFileInfo)只认文件自身资源，.msc 为 0 时拿不到专属图标

ms-settings 14 项（无文件）两个选择：
a) imageres.dll(369组)/shell32.dll(335组)/ddores.dll(151组) 挑 —— 序号跨系统版本可能变
b) Segoe Fluent Icons 字体字形（本机已装，Win11 设置应用同款）—— 码点跨版本稳定，需查码点

建议落地：后端加 extract_system_icon(file,index,size) 命令；
SystemTool 加 iconRes 字段；pickTool 改调后端提取（与 APPX 标签同路）；
可选做"系统图标浏览器"对话框（枚举 imageres/shell32/ddores 网格挑选）。

验证脚本留在 .temp/：icon_probe.py lnk_probe.py res_probe.py detail_probe.py lib_probe.py
make_sheet.py make_sheet2.py（产物：系统图标对照.png、可疑DLL全部图标.png、负数资源ID验证.png）
隔离环境 envs/default 已安装 Pillow（用于图标拼图/校验图）。

## 侧栏删除子分类的导航保持 + 系统/APPX 自定义图标（已完成）

问题1：侧栏右键删除子分类后，顶部/侧栏导航会跳到第一个一级分类。
根因：store.deleteCategory 末尾无条件把 state.currentCategoryId 重置为第一个可见顶级分类。
修复（src/store/index.ts deleteCategory）：
- 删除前记录 prevSelected（当前选中）与 fallbackParentId（被删分类的 parent_id）
- 新增 removedIds：move 策略只含 {id}（子分类上提保留），delete/orphan 为整棵子树
- 仅当 prevSelected 确实消失时才切换：优先落到 fallbackParentId，否则第一个可见顶级分类；
  否则原样保持 → 删除别的子分类时继续停留在当前顶级分类
顺带修复：move 策略原先只删当前分类，子分类 parent_id 悬空、从前台导航彻底消失（等于丢数据）。
现改为把直属子分类上提一级挂到被删分类的父级（is_top_level / sort_order 同步重排）。

问题2：系统功能/APPX 条目不能自定义图标。
修复（src/components/dialogs/EntryEditor.vue）：
- 图标区块去掉 v-if="!isUriType"，所有类型都显示（封面仍仅非 URI 类型）
- 新增 resolveSystemIconSource()：优先条目 icon_source，其次按 SYSTEM_TOOLS 用
  target+launch_args 反查（旧 emoji 条目也能升级）
- refreshIcon()：system 类型先把解析出的 spec 写回 form.icon_source 再交给后端 force 重提取；
  无来源时提示重新选择目标
- 按钮文案：URI 类型显示「恢复默认图标 / 恢复中...」，其余仍为「重新提取图标」
- applySystemSelection：选择器没取到图标时清空旧图标（type=default），避免残留上一个目标的图标
- 自定义图标不清 icon_source，保证随时可恢复默认；APPX 恢复默认走后端按 relative_path 重提取
验证：vue-tsc --noEmit 通过；vite build 通过。
